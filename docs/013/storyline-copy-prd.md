# 复制故事前 N 章 PRD

## 背景

用户在创作过程中可能希望保留当前故事的一段稳定前缀，并从某一章开始尝试不同的发展方向。当前系统只能在原故事上继续续写、重写或互动，无法把前若干章复制为一条新的故事线。

本期新增「复制故事」能力：用户可以在故事详情页指定第 N 章，将原故事第 1 章到第 N 章复制为一个完全独立的新故事，并立即在新故事上继续创作。

## 目标

- 用户可以从故事详情页发起复制。
- 用户可以指定复制第 1 章到第 N 章。
- N 默认是当前正在阅读的章节，并允许修改。
- 用户可以在复制时为新故事填写独立标题。
- 新故事保留所选章节的全部阅读内容和生成记录。
- 新故事继承不超过第 N 章的最近安全上下文，不得包含后续剧情信息。
- 复制成功后直接打开新故事的第 N 章，用户可以立即续写、重写或互动。
- 原故事和新故事在复制完成后完全独立，后续修改互不影响。

## 非目标

- 不记录或展示新故事来自哪个原故事。
- 不支持原故事与副本之间的后续同步、合并或冲突处理。
- 不支持只复制某个非连续章节区间。
- 不支持排除第 N 章内的互动分段。
- 不支持跨用户复制故事。
- 不支持批量复制多个故事。
- 不在本期提供通用的故事重命名能力。
- 不为复制请求增加服务端幂等键或幂等记录表。
- 不复制正在运行的生成任务、上下文提取任务或页面内的推理内容。

## 核心概念

### 原故事

用户发起复制操作时正在查看的故事。

原故事只用于本次读取。复制完成后，新故事不保存原故事 ID，也不与原故事建立持续关联。

### 截止章节

截止章节记为 N，表示复制原故事中 `第 1 章` 到 `第 N 章` 的全部内容。

N 必须是整数，并满足：

```text
1 <= N <= 原故事总章节数
```

### 新故事

新故事是复制操作产生的一条独立故事线，拥有新的故事 ID 和新的分段 ID。

新故事创建后：

- 原故事的后续修改不会影响新故事。
- 新故事的后续修改不会影响原故事。
- 新故事可以再次使用「复制故事」功能。
- 新故事可以与其他故事重名。

## 已确认决策

- 复制结果是完全独立的故事，不保留来源关系。
- 功能入口位于故事详情页。
- N 默认取当前阅读章节，用户可以在弹窗中修改。
- 第 N 章中的续写正文、互动对话和动作结果等全部复制。
- 副本继承不超过第 N 章的最近安全结构化上下文。
- 如果不存在恰好截至 N 的完整快照，使用更早的最近安全快照并保留待提取轮次，不自动调用 LLM 补齐。
- 原故事正在生成或提取上下文时禁止复制。
- 复制时必须填写独立标题。
- 默认标题为「原标题（副本）」。
- 标题允许重复。
- 标题只在复制时填写，本期不提供创建后的重命名入口。
- 标题展示在故事列表和故事详情页顶部。
- 复制成功后直接打开新故事第 N 章，并显示成功 Toast。
- 复制失败后保留弹窗中的标题和章节输入，允许用户重试。
- 已复制故事可以继续被复制。
- 已复制分段的生成指令、模型、耗时和 Token 记录完整保留。
- 前端提交过程中禁用重复提交，不增加服务端严格幂等机制。

## 用户场景

### 从当前章节创建独立故事

1. 用户打开一个故事并阅读到第 6 章。
2. 用户打开详情页顶部的「更多」菜单。
3. 用户点击「复制故事」。
4. 弹窗默认填写原标题加「（副本）」，截止章节默认为 6。
5. 用户修改标题，保留截止章节为 6。
6. 用户提交复制。
7. 系统创建包含第 1 至第 6 章的新故事。
8. 页面跳转到新故事第 6 章。
9. 页面显示「已复制前 6 章」成功 Toast。
10. 用户在新故事上继续续写，原故事不受影响。

### 修改默认截止章节

1. 用户正在阅读原故事第 8 章。
2. 用户打开复制弹窗，默认截止章节为 8。
3. 用户把截止章节改为 4。
4. 系统创建只包含第 1 至第 4 章的新故事。
5. 新故事上下文不得包含第 5 章及之后的角色状态、事实或场景信息。

### 原故事正在处理中

1. 原故事正在生成正文或提取上下文。
2. 用户尝试复制故事。
3. 前端在已知故事正在生成时禁用提交。
4. 服务端检测到故事锁已被占用时返回冲突。
5. 弹窗保持打开并提示「当前故事正在处理中，请稍后重试」。
6. 用户填写的标题和截止章节保持不变。

## 产品入口

故事详情页顶部展示：

- 当前故事标题。
- 「更多」按钮。
- 「返回列表」按钮。

点击「更多」后展示：

- 「复制故事」：打开复制弹窗。
- 「上下文」：进入现有上下文调试页面，是原「调试」入口的产品文案调整。

「复制故事」在用户查看任意正式章节时都可使用，不依赖用户是否正在查看最后一章。

## 故事标题

### 展示规则

- 故事列表展示故事标题。
- 故事详情页顶部展示故事标题。
- 普通故事继续使用当前规则，从初始正文派生展示标题。
- 复制产生的新故事使用用户在复制弹窗中提交的显式标题。
- 显式标题不改变第一章正文内容。

### 输入规则

- 默认值为「原标题（副本）」。
- 默认值超过长度限制时，优先保留「（副本）」后缀并截断原标题。
- 提交前去除首尾空白。
- 标题不能为空。
- 标题最长 80 个字符。
- 允许与当前用户已有故事重名。
- 本期不提供复制完成后的标题修改入口。

## 复制弹窗

### 展示内容

- 标题：「复制故事」。
- 新故事标题输入框。
- 截止章节数字输入框。
- 原故事总章节数提示，例如「共 12 章」。
- 主按钮：「创建副本」。
- 取消或关闭按钮。

### 截止章节控件

- 使用数字输入框，并提供浏览器或组件步进能力。
- 最小值为 1。
- 最大值为原故事总章节数。
- 默认值为打开弹窗时的当前阅读章节。
- 输入小数、非数字、0、负数或超过总章节数时，不允许提交并展示字段错误。

### 提交状态

- 提交后主按钮进入加载状态。
- 请求结束前禁用标题、截止章节和主按钮，避免用户连续点击。
- 用户关闭弹窗后再次打开时，重新根据当前故事和当前章节生成默认值。
- 请求失败时弹窗保持打开，恢复输入能力并保留用户输入。

## 复制范围

### 必须复制

- `chapterIndex <= N` 的所有故事分段。
- 初始正文。
- 续写正文。
- 第 N 章及之前的全部互动分段。
- 每个生成分段的生成模式和用户指令。
- 模型、耗时、输入 Token、输出 Token、总 Token 和目标长度。
- 每个生成分段用于重写的历史上下文快照。
- 截至第 N 章可用的结构化故事上下文。
- 结构化上下文的提取进度，使新故事能够继续增量提取。

### 不得复制

- 第 N 章之后的任何正文或互动分段。
- 第 N 章之后才产生的世界事实、人物状态或当前场景信息。
- 原故事 ID、来源关系或分支关系。
- 原故事当前正在运行的生成任务。
- 原故事当前正在运行的上下文提取任务。
- 未保存的流式正文、输入草稿或页面状态。
- LLM 推理内容。

### 标识与时间

- 新故事获得新的故事 ID。
- 每个复制分段获得新的分段 ID。
- 上下文中引用的分段 ID 必须全部指向新故事中的新分段 ID。
- 新故事的创建时间和更新时间使用复制成功时间。
- 原故事的创建时间和更新时间不发生变化。

## 上下文一致性要求

复制结果必须表示“原故事刚完成第 N 章时可用的状态”，而不是简单复制原故事当前最新状态。

具体要求：

- 新故事上下文最多只能提取到已复制分段。
- 如果原故事当前上下文尚未覆盖全部已复制章节，新故事保留相同提取进度，剩余分段可继续增量提取。
- 如果原故事当前上下文已经覆盖到第 N 章之后，系统必须回退到第一个未复制分段生成前保存的上下文快照。
- 如果回退快照只提取到早于 N 的章节，副本保留该安全游标，并把游标之后的已复制分段视为待提取内容。
- 本期不要求通过复制操作构造一个当前数据库中不存在的“恰好截至 N”上下文。
- 上下文中的所有正文来源引用必须重映射到新分段 ID。
- 任一上下文引用无法重映射时，复制整体失败，不允许创建部分副本。
- 复制过程不得触发新的 LLM 调用。

## 成功行为

复制成功后：

1. 关闭复制弹窗。
2. 跳转到新故事详情页。
3. 阅读器定位到新故事第 N 章。
4. 显示 Toast：「已复制前 N 章」。
5. 新故事出现在故事列表顶部。
6. 新故事标题使用用户提交的显式标题。

新故事只有第 1 章时：

- 可以续写。
- 可以互动。
- 因为没有生成分段，不展示重写操作。

## 失败行为

### 输入错误

- 标题为空或超过 80 个字符：在标题输入框附近展示错误。
- N 不是有效整数或超出范围：在章节输入框附近展示错误。
- 不发送请求。

### 故事不存在或无权访问

- 服务端按故事不存在处理。
- 前端关闭复制流程并进入现有故事不存在状态，不能泄露其他用户故事是否存在。

### 故事正在处理中

- 服务端返回冲突。
- 弹窗保持打开。
- 展示「当前故事正在处理中，请稍后重试」。
- 保留标题和 N。

### 保存失败

- 弹窗保持打开。
- 展示「复制故事失败，请稍后重试」。
- 保留标题和 N。
- 服务端必须保证事务回滚，不留下空故事或部分分段。

### 网络结果不确定

本期只在前端提交期间禁止重复点击，不提供服务端严格幂等。若请求超时，用户可以重试，但极端情况下可能产生两个内容相同的副本。该限制需要在技术方案和测试说明中明确。

## 权限与并发

- 只能复制当前登录用户自己的故事。
- 无权访问的故事统一表现为不存在。
- 复制操作与正文生成、重写、互动和上下文提取共用故事级锁。
- 获取锁失败时不等待、不排队，直接返回冲突。
- 复制新故事不继承原故事上的任何运行中任务状态。

## 验收标准

### 基础复制

- 给定 10 章故事，选择 N=6 后，新故事恰好包含 6 章。
- 新故事正文与原故事前 6 章一致。
- 原故事第 7 至第 10 章不出现在新故事中。
- 新故事和原故事拥有不同故事 ID。
- 所有复制分段拥有新分段 ID。

### 互动内容

- 第 N 章包含多轮互动内容时，互动内容全部出现在副本第 N 章。
- 第 N+1 章及之后的互动内容不出现在副本中。

### 标题

- 弹窗默认展示「原标题（副本）」。
- 用户可以修改默认标题。
- 新标题展示在故事列表和详情页顶部。
- 两个故事可以使用相同标题。
- 第一章正文不因标题变化而被修改。

### 上下文

- 截止章节之后产生的事实和人物状态不出现在副本上下文。
- 副本上下文中的所有 `sourceSegmentIds` 都属于副本。
- 上下文提取进度落后于 N 时，副本可以继续提取剩余已复制分段。
- 复制后立即续写时，模型使用最近安全结构化上下文和近期正文历史，且不得获得 N 之后的信息。
- 最近安全快照早于 N 时，上下文调试页能正确展示剩余待提取轮次。
- 重写副本最后一个生成分段时，可以使用重映射后的历史上下文快照。

### 边界

- N=1 可以成功复制并继续续写。
- N=总章节数可以成功复制完整故事。
- N=0、负数、小数、非数字或超过总章节数时不能提交。
- 复制只有初始正文的故事时，不展示重写操作。
- 已复制故事可以再次复制。

### 并发与失败

- 原故事正在生成时复制返回冲突，不创建新故事。
- 原故事正在提取上下文时复制返回冲突，不创建新故事。
- 数据库中途写入失败时不留下新故事或部分分段。
- 请求失败后弹窗保留用户输入并允许重试。

## 发布与观测

- 复制接口记录成功、失败、冲突、复制章节数和复制分段数。
- 日志不得记录故事正文、上下文 JSON 或用户标题全文。
- 本期不增加独立埋点平台；沿用服务端结构化日志和前端现有错误反馈。
- 不需要调用 LLM，因此复制耗时主要由 SQLite 事务和分段数量决定。
