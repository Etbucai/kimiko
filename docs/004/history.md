# 引入历史消息记录

StoryAgent 在生成故事时，引入同一故事线的历史消息记录。

本期不使用“对话”作为产品概念和命名，统一使用“故事线”描述一段连续续写的故事历史。

## 背景

上一阶段 StoryAgent 已支持登录用户在单页中输入故事正文和续写指令，并通过 WebSocket 获得流式续写结果。

当前问题是：每次生成仍然更像一次独立请求。用户需要反复手动维护完整上下文，续写指令也没有形成可被后续生成参考的历史轨迹。

本期目标是在不引入复杂历史管理 UI 的前提下，让 StoryAgent 自动保存并使用同一故事线的近期历史，使后续续写能够参考最近的正文片段和用户指令轨迹。

## 用户定位

- 本轮继续面向内部测试者。
- 内部测试者的目标是验证一个移动端优先的连续续写体验是否可用：输入初始故事正文和续写指令后，后续只需要继续输入新的续写指令，StoryAgent 会把成功生成的内容累积成故事正文。

## 本轮目标

- 引入“故事线”作为历史隔离容器。
- 登录用户进入 StoryAgent 页面时，自动恢复自己最近的故事线。
- 没有历史故事线时，进入空白初始态。
- 首轮生成需要用户提供初始故事正文和续写指令。
- 后续生成只需要用户提供续写指令。
- Agent 成功完成的续写内容会作为故事正文的一部分累积展示。
- 服务端保存同一故事线的历史轮次，并在生成时注入最近 N 轮历史。
- 最近 N 轮默认值为 20，并由服务端 `.env` 环境配置控制。
- 页面移动端优先，续写指令输入框固定在页面底部。

## 核心概念

### 故事线

故事线是一段连续续写的故事历史。

规则：
- 故事线按登录用户隔离。
- 一个用户可以在数据层拥有多条故事线。
- 本期页面只自动恢复最近故事线，不提供故事线列表。
- 本期不提供主动新建故事线入口。
- 本期不提供切换、删除、重命名、收藏、分享等故事线管理能力。

### 初始故事正文

初始故事正文是用户在空白故事线中输入的第一段正文。

规则：
- 没有可恢复故事线时，页面展示初始故事正文输入区域。
- 首轮生成时，初始故事正文必填。
- 首轮成功完成后，初始故事正文进入只读正文区。
- 故事线进入已有正文状态后，用户不再编辑正文。

### 轮次历史

一次成功完成的续写生成记为一轮历史。

每轮历史包含：
- 用户本轮续写指令。
- Agent 本轮输出的续写正文。
- 本轮生成元数据：模型、耗时、Token。

规则：
- 只有成功完成并保存成功的生成会成为正式历史。
- 取消、生成失败、保存失败的临时文本不进入历史。
- 用户指令不与 Agent 输出正文混排。
- 用户指令可用于后续生成上下文，但本期不在正文区展示指令历史。

### 历史窗口

历史窗口表示服务端生成时注入 prompt 的最近轮次数量。

规则：
- 默认注入最近 20 轮。
- 具体轮数由服务端 `.env` 环境配置控制。
- 历史窗口只影响 LLM 生成上下文。
- 历史窗口不会删除数据库中的完整故事线历史。
- 历史窗口不会裁剪页面展示的完整故事正文。
- 当故事线超过历史窗口时，服务端生成时只注入最近 N 轮对应的正文片段和指令轨迹。
- 初始故事正文不始终保留在 LLM 上下文中；当它不属于最近 N 轮上下文时，不再注入。

## 用户链路

### 无历史故事线

1. 内部测试者登录后进入 StoryAgent 页面。
2. 服务端没有找到该用户可恢复的故事线。
3. 页面进入空白初始态。
4. 页面展示初始故事正文输入区域。
5. 页面底部固定展示续写指令输入框和生成按钮。
6. 用户填写初始故事正文。
7. 用户填写续写指令。
8. 用户点击生成按钮。
9. 生成期间，页面在正文尾部临时追加流式输出。
10. 生成成功且保存成功后，临时输出成为正式正文段。
11. 页面自动清空底部续写指令输入框。
12. 页面弱展示最新一轮模型、耗时、Token。

### 有历史故事线

1. 内部测试者登录后进入 StoryAgent 页面。
2. 页面自动恢复该用户最近的故事线。
3. 页面展示已累积的只读故事正文。
4. 正文中不同 Agent 输出段之间可以展示轻量弱提示分隔符。
5. 分隔符仅用于 UI 展示，不作为正文内容保存，也不发送给 LLM。
6. 页面底部固定展示续写指令输入框和生成按钮。
7. 用户只填写新的续写指令。
8. 用户点击生成按钮。
9. 服务端读取当前故事线，并基于最近 N 轮历史构造生成上下文。
10. 生成期间，页面在正文尾部临时追加流式输出。
11. 生成成功且保存成功后，临时输出成为正式正文段。
12. 页面自动清空底部续写指令输入框。
13. 页面弱展示最新一轮模型、耗时、Token。

## 页面规则

- 页面继续作为 StoryAgent 的核心页面。
- 页面移动端优先。
- 页面主体展示故事正文。
- 故事正文在首轮成功后为只读累积正文。
- 底部固定展示续写指令输入框和生成按钮。
- 用户指令不展示在正文中。
- Agent 输出作为正文内容累积展示。
- 生成中的流式文本展示在正文尾部，但在完成前属于临时文本。
- 完成前的临时文本不属于正式故事线正文。
- 成功完成后，临时文本转为正式正文。
- 取消或失败后，临时文本从正文中移除。
- 分隔符仅作为轻量弱提示，用于区分 Agent 输出段落。
- 分隔符不进入正文内容，不进入历史记录，不进入 LLM prompt。
- 最新一轮模型、耗时、Token 以弱化信息展示，不污染正文阅读。
- 本期不展示历史指令列表。
- 本期不展示故事线列表。
- 本期不提供新建故事线按钮。
- 本期不提供正文编辑能力。

## 输入规则

### 初始故事正文

- 仅在没有可恢复故事线时展示。
- 首轮生成时必填。
- 初始故事正文允许任意非空文本。
- 初始故事正文为空时，在输入区域附近提示用户填写。
- 首轮成功后，初始故事正文进入只读正文区。

### 续写指令

- 始终展示在页面底部固定输入区。
- 每轮生成时必填。
- 续写指令应描述接下来要发生的主要情节和人物行动。
- 续写指令为空时，在底部输入区附近提示用户填写。
- 成功完成后，续写指令输入框自动清空。
- 生成失败、保存失败或取消后，续写指令输入框保留原内容，方便用户重试或修改。

## 输出规则

- 沿用 StoryAgent 既有输出规则。
- 输出只包含新生成的续写内容，不重复用户可见正文。
- 输出为纯正文段落。
- 输出不包含标题、解释、列表、调试信息或“以下是续写”等前缀。
- 输出长度目标为 800-1200 字。
- 输出语言跟随故事正文的主要语言。
- 输出应承接服务端提供的近期正文片段、人物、事件、语气和上下文。
- 输出应遵循当前续写指令。
- 输出应参考最近 N 轮历史中的指令轨迹。

## 历史使用规则

- 服务端负责读取和注入历史。
- 前端不手动拼接历史消息。
- 前端不把完整历史记录传回服务端。
- 后续生成请求只提交当前故事线标识和本轮续写指令。
- 服务端使用 SQLite 保存故事线和完成轮次。
- 服务端生成时只使用当前登录用户自己的故事线历史。
- 服务端生成时只使用当前故事线内的历史。
- 服务端不会跨用户、跨故事线混用历史。
- 当故事线已有活跃生成任务时，服务端拒绝同一故事线上的并发生成，避免输出顺序错乱。
- 历史窗口默认 20 轮，可通过服务端 `.env` 环境配置调整。
- 当轮次数超过历史窗口时，服务端只向 LLM 注入最近 N 轮相关上下文。
- 裁剪只影响本次 LLM 上下文，不影响数据库保存和页面展示。

## 异常反馈

### 无故事线

- 用户没有任何故事线时，这是正常状态。
- 页面展示空白初始态，允许用户输入初始故事正文和续写指令。

### 恢复失败

- 如果进入页面时恢复最近故事线失败，页面展示错误页。
- 恢复失败不自动退回空白初始态。
- 鉴权失效仍进入登录流程。

### 生成失败

- 生成失败时，正式故事正文保持不变。
- 生成失败时，已流出的临时文本从正文中移除。
- 生成失败时，保留底部续写指令输入框内容。
- 生成失败时，页面提示用户本次生成失败，可以重试。
- 生成失败不会展示技术错误详情。

### 保存失败

- LLM 已完成但写入故事线历史失败时，视为本轮生成失败。
- 保存失败时，正式故事正文保持不变。
- 保存失败时，临时文本不转为正式正文。
- 保存失败时，保留底部续写指令输入框内容。
- 保存失败时，页面提示用户本次生成失败，可以重试。

### 用户取消

- 用户取消生成后，正式故事正文保持不变。
- 用户取消生成后，已流出的临时文本从正文中移除。
- 用户取消生成后，本轮不写入历史。
- 用户取消生成后，保留底部续写指令输入框内容。
- 页面提示用户本次生成已取消。

### 并发生成

- 同一故事线同一时间只允许一个活跃生成任务。
- 如果用户在其他页面或设备上已经触发同一故事线生成，本页面再次生成时应收到可理解的忙碌提示。
- 并发失败不会改变正式故事正文。
- 并发失败不会清空续写指令。

## 验收标准

- 登录用户首次访问且没有故事线时，看到空白初始态。
- 空白初始态展示初始故事正文输入区域。
- 页面底部固定展示续写指令输入框和生成按钮。
- 首轮生成时，初始故事正文为空会展示字段级提示。
- 每轮生成时，续写指令为空会展示字段级提示。
- 首轮生成成功后，初始故事正文和 Agent 输出共同展示为只读故事正文。
- 用户再次进入页面时，自动恢复自己的最近故事线。
- 有历史故事线时，页面不要求用户再次输入完整故事正文。
- 有历史故事线时，用户只需要输入续写指令即可继续生成。
- 生成期间，流式文本在正文尾部临时展示。
- 生成成功且保存成功后，临时文本转为正式正文。
- 生成成功后，底部续写指令输入框自动清空。
- 生成成功后，页面展示最新一轮模型、耗时、Token。
- 取消生成后，临时文本从正文中移除，正式正文保持不变。
- 生成失败后，临时文本从正文中移除，正式正文保持不变。
- 保存失败后，临时文本不进入正式正文。
- 取消、生成失败、保存失败后，续写指令输入框保留原内容。
- 用户指令不会混排到故事正文中。
- UI 分隔符不会保存为正文内容。
- UI 分隔符不会进入 LLM prompt。
- 服务端只使用当前用户、当前故事线的历史。
- 服务端默认使用最近 20 轮历史。
- 服务端历史窗口可以通过 `.env` 环境配置调整。
- 超过历史窗口后，页面仍展示完整故事正文。
- 超过历史窗口后，数据库仍保留完整故事线历史。
- 超过历史窗口后，LLM 上下文只使用最近 N 轮相关上下文。
- 同一故事线并发生成会被服务端拒绝。
- 没有任何故事线时，页面进入空白初始态。
- 恢复最近故事线失败时，页面展示错误页。

## 本轮不做

- 不做故事线列表。
- 不做主动新建故事线入口。
- 不做故事线切换。
- 不做故事线删除。
- 不做故事线重命名。
- 不做故事线收藏、分享、导出。
- 不做正文编辑。
- 不做用户手动选择哪些历史参与生成。
- 不做历史摘要。
- 不做跨故事线检索。
- 不做跨用户共享历史。
- 不做本地存储兜底。
- 不做自动重试。
- 不做用户偏好配置。
