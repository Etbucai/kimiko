# 引入故事线角色摘要

StoryAgent 在多轮故事生成时，引入同一故事线的角色摘要能力，用于降低长期续写中的角色身份、关系和状态漂移。

本期不引入完整 Canon 系统，不引入多 Agent 自治协作，不提供用户可编辑的设定管理能力。系统只在每轮正文生成完成后，记录重要角色摘要，并在后续续写中使用这些摘要帮助 Agent 延续角色设定。

## 背景

上一阶段 StoryAgent 已支持登录用户的故事线持久化、多轮续写、最近故事线恢复和最近 N 轮历史注入。

当前问题是：随着故事线变长，仅依赖最近 N 轮正文和用户指令会逐步丢失早期角色信息。典型表现包括：

- 角色身份被遗忘或混淆。
- 角色之间的关系前后不一致。
- 角色当前处境、目标或行动状态被跳过。
- 新一轮续写只承接最近文本，忽略较早建立的人设。

本期目标是在不显著改变用户创作链路的前提下，让 StoryAgent 自动维护重要角色摘要，使后续续写更稳定地承接角色身份、关系和状态。

## 用户定位

- 本轮继续面向内部测试者。
- 内部测试者的目标是验证：在多轮续写中，StoryAgent 是否能更稳定地记住重要角色，减少明显的角色跳戏。

## 本轮目标

- 系统在每次成功生成正文后，记录本轮故事中涉及的重要角色摘要。
- 角色摘要只覆盖重要角色，不覆盖完整世界观、事件表、任务表或伏笔系统。
- 后续续写时，Agent 能参考同一故事线下已经记录的角色摘要。
- 正文生成完成后、角色摘要记录完成前，页面需要提示用户系统正在记录摘要。
- 角色摘要记录完成后，本轮续写才算正式完成。
- 角色摘要内容本期不直接展示给用户，也不提供用户编辑入口。

## 非目标

- 本期不做完整 CanonSnapshot。
- 本期不做事件时间线、任务、伏笔、世界规则等结构化管理。
- 本期不做冲突校验、自动重写或修复。
- 本期不让多个 Agent 自治讨论或规划。
- 本期不展示角色摘要列表。
- 本期不提供角色摘要编辑、删除、回滚能力。
- 本期不提供前端调试面板。

## 核心概念

### 角色摘要

角色摘要是系统为同一故事线维护的内部连续性信息，用于帮助 Agent 在后续续写中稳定承接重要角色。

角色摘要只记录对续写连续性有直接帮助的信息：

- 角色姓名或称呼。
- 角色身份。
- 角色之间的重要关系。
- 角色稳定动机。
- 角色当前处境或状态。

角色摘要不追求文学性，不是展示给用户阅读的正文，也不是完整角色卡。

### 重要角色

重要角色指对当前故事线推进有持续影响的角色。

判断规则：

- 反复出现的角色应进入角色摘要。
- 当前轮次中承担关键行动、冲突或关系变化的角色应进入角色摘要。
- 只作为背景、路人或一次性氛围描写出现的角色，不要求进入角色摘要。
- 已进入摘要的角色，如果本轮出现新的身份、关系或状态变化，应更新摘要。

### 正式完成

本期中，一轮续写的正式完成条件包含两部分：

1. Agent 成功生成正文。
2. 系统成功记录角色摘要。

只有两者都成功，本轮续写才进入正式故事线历史，并向用户展示为完成状态。

## 用户链路

### 首轮生成

1. 用户在空白故事线中输入初始故事正文。
2. 用户输入续写指令。
3. 用户点击生成续写。
4. 页面展示流式生成中的临时正文。
5. 正文流式生成完成后，页面继续保留临时正文。
6. 页面提示用户：正在记录角色摘要。
7. 角色摘要记录成功后，本轮续写正式完成。
8. 临时正文转为正式正文。
9. 页面清空续写指令输入框。

### 后续续写

1. 用户在已有故事线中输入新的续写指令。
2. 用户点击生成续写。
3. Agent 基于当前故事线历史和角色摘要生成新正文。
4. 页面展示流式生成中的临时正文。
5. 正文流式生成完成后，页面继续保留临时正文。
6. 页面提示用户：正在记录角色摘要。
7. 角色摘要记录成功后，本轮续写正式完成。
8. 临时正文转为正式正文。
9. 页面清空续写指令输入框。

## 页面规则

- 页面主体仍然展示故事正文。
- 角色摘要内容本期不展示在页面中。
- 生成正文时，页面展示生成中的临时正文。
- 正文生成结束但角色摘要尚未记录完成时，临时正文继续展示。
- 记录角色摘要期间，页面展示轻量状态提示。
- 推荐状态文案为：正在记录角色摘要...
- 记录角色摘要期间，底部输入区仍处于生成中状态。
- 记录角色摘要期间，用户仍可以取消本轮生成。
- 角色摘要记录成功后，页面进入完成状态。
- 角色摘要记录失败时，页面进入生成失败状态。

## 取消规则

- 用户在正文流式生成阶段取消，本轮不进入正式故事线历史。
- 用户在记录角色摘要阶段取消，本轮也不进入正式故事线历史。
- 取消后，临时正文从页面移除。
- 取消后，续写指令输入框保留原内容，方便用户修改或重试。
- 取消后，页面提示用户本次生成已取消。

## 失败规则

### 正文生成失败

- 正文生成失败时，本轮不进入正式故事线历史。
- 已展示的临时正文从页面移除。
- 续写指令输入框保留原内容。
- 页面提示用户本次生成失败，可以重试。

### 角色摘要记录失败

- 即使正文已经生成完成，只要角色摘要记录失败，本轮仍视为失败。
- 失败后，本轮正文不进入正式故事线历史。
- 临时正文从页面移除。
- 续写指令输入框保留原内容。
- 页面提示用户本次生成失败，可以重试。
- 页面不向用户暴露摘要记录的技术细节。

### 保存失败

- 如果正式故事线保存失败，本轮视为失败。
- 失败后，正式故事正文保持不变。
- 临时正文从页面移除。
- 续写指令输入框保留原内容。
- 页面提示用户本次生成失败，可以重试。

## 摘要使用规则

- 角色摘要只在同一登录用户、同一故事线内使用。
- 不同用户之间不共享角色摘要。
- 不同故事线之间不共享角色摘要。
- 角色摘要用于帮助后续生成，不作为用户可见正文。
- 角色摘要不替代最近 N 轮历史。
- 最近 N 轮历史仍用于承接局部语气、节奏和上下文。
- 角色摘要用于补足历史窗口外的重要角色信息。

## 输出规则

- Agent 输出仍然只包含新生成的续写正文。
- Agent 不应在正文中输出角色摘要。
- Agent 不应在正文中解释自己如何使用角色摘要。
- Agent 不应输出标题、列表、调试信息或“以下是续写”等前缀。
- Agent 应优先保持重要角色的身份、关系、动机和当前状态一致。

## 验收标准

- 首轮正文生成完成后，页面能进入“正在记录角色摘要”的状态。
- 记录角色摘要期间，页面保留临时正文。
- 记录角色摘要期间，用户可以取消本轮生成。
- 在记录角色摘要阶段取消后，本轮正文不会进入正式故事线历史。
- 角色摘要记录成功后，本轮正文才转为正式正文。
- 角色摘要记录失败后，本轮视为生成失败，正式故事正文保持不变。
- 角色摘要内容不会展示给用户。
- 后续续写时，重要角色的身份不会明显丢失。
- 后续续写时，重要角色之间的关系不会明显错乱。
- 后续续写时，重要角色的当前处境或状态能被合理承接。
- 最近 N 轮历史仍然正常生效。
- 角色摘要不会跨用户或跨故事线使用。

## 后续演进

如果一期验证有效，后续可以逐步扩展：

- 从重要角色摘要扩展到世界观规则摘要。
- 从摘要快照扩展到增量变更记录。
- 增加正文与摘要之间的一致性校验。
- 在严重破坏设定时尝试自动修复正文。
- 在前端提供只读摘要调试视图。
- 提供用户可编辑的角色设定管理能力。

这些能力不进入本期范围。
