# 为故事线添加重写功能

StoryAgent 在已有故事线中增加「重写上一段」能力。用户可以针对最近一次生成的正文输入重写指令，让 Agent 基于上一次生成内容重新生成这一段，而不是继续向后续写。

本期重写只面向最新生成段，不支持重写任意历史段，不引入版本列表、回滚、分支故事线或人工编辑正文能力。

## 背景

当前故事线支持：

- 新建故事线。
- 基于已有故事线继续续写。
- 每轮生成后记录角色摘要，并在后续续写中注入摘要。
- 列表页和详情页展示故事线当前正式快照。

但用户在某一轮续写不满意时，只能继续追加新指令修正，无法直接替换上一轮生成结果。这样会把不满意的正文留在正式历史中，后续续写和角色摘要也会继续受它影响。

本期目标是给用户一个低成本的「重写上一段」入口：保留当前故事线结构，只替换最新生成段，让后续故事从新版本继续发展。

## 用户定位

- 本轮继续面向内部测试者。
- 内部测试者的主要目标是快速调整最近一次生成结果，例如：
  - 不要转变场景。
  - 文风更加轻快。
  - 增加对气味的描写。
  - 让角色反应更克制。

## 本轮目标

- 用户可以对同一故事线的最新生成段发起重写。
- 重写时，用户必须输入「重写指令」。
- 重写 prompt 必须包含上一次生成内容。
- 重写成功后，新正文原地替换旧生成段。
- 重写成功后，故事线只保留替换后的正式版本。
- 重写成功后，角色摘要必须基于替换后的版本更新。
- 重写失败或取消时，旧正式正文保持不变。
- 续写草稿和重写草稿相互独立，互不覆盖。

## 非目标

- 本期不支持重写初始正文。
- 本期不支持重写任意历史生成段。
- 本期不保留重写前后的多版本记录。
- 本期不提供版本对比、恢复旧版本或分支故事线。
- 本期不把重写结果作为新段追加到故事线末尾。
- 本期不展示或编辑角色摘要。
- 本期不做旧数据兼容；可以按当前玩具项目策略调整数据库结构和迁移。

## 核心概念

### 重写

重写是对最新 generated segment 的重新生成。

重写不是续写。续写会在故事线末尾新增 generated segment；重写会替换目标 generated segment 的正文和生成元数据，segment 数量不变。

### 重写指令

重写指令是用户对本次重新生成提出的要求。

示例：

- 不要转变场景。
- 文风更加轻快。
- 增加对气味的描写。
- 保留原来的冲突，但让角色语气更克制。

重写指令不能为空，长度上限沿用续写指令的 8000 字限制。

### 目标生成段

本期目标生成段只能是故事线中最新的 generated segment。

如果故事线没有 generated segment，则没有可重写内容，不显示重写入口。

### previousSummary

为了让重写后的角色摘要不受旧版本污染，每个 generated segment 需要保存该段生成前的角色摘要快照，命名为 previousSummary。

规则：

- 首轮生成段的 previousSummary 为空摘要。
- 续写生成段的 previousSummary 是续写开始前故事线的当前角色摘要。
- 重写某段时，服务端使用该段保存的 previousSummary 作为摘要提取的旧状态。
- 重写成功后，当前故事线角色摘要基于 previousSummary 和新正文重新生成。
- 重写成功后，目标段的 previousSummary 保持为生成前状态。

本期仍只维护角色摘要，不引入完整 previousState 或 CanonSnapshot。后续扩展事件、设定、世界规则时，可以沿用“每个生成段保存生成前状态快照”的设计。

## 用户链路

### 进入重写模式

1. 用户打开已有故事线详情页。
2. 页面展示正式故事正文。
3. 最新 generated segment 上显示「重写」按钮。
4. 用户点击「重写」。
5. 页面底部输入区切换为重写模式。
6. 输入框标签显示「重写指令」。
7. 输入框占位提示用户输入具体改写要求。
8. 主按钮显示「生成重写」。
9. 底部输入区显示「取消重写」次要按钮。

只有页面空闲时才显示或启用「重写」按钮。生成中、摘要记录中或重写中，不允许再触发新的重写。

### 草稿规则

- 续写草稿和重写草稿是两份独立状态。
- 用户已有续写草稿时，点击「重写」不需要二次确认，也不覆盖续写草稿。
- 用户退出重写模式后，续写草稿应恢复显示。
- 用户点击「取消重写」只退出重写模式，不提交请求。
- 重写成功后，清空重写指令，并退出重写模式。
- 重写成功后，续写草稿保持原样。
- 重写失败或取消生成后，保留重写指令，方便用户修改后重试。

### 重写生成

1. 用户在重写模式输入重写指令。
2. 用户点击「生成重写」。
3. 页面进入生成中状态，底部按钮显示「取消生成」。
4. 旧正式正文继续展示，不被临时文本覆盖。
5. 页面在目标段下方展示「重写中」临时草稿。
6. 服务端流式返回新正文 chunk。
7. 正文流式生成完成后，页面保留临时草稿。
8. 页面进入「正在记录角色摘要...」状态。
9. 摘要生成和保存成功后，服务端返回正式故事线快照。
10. 前端用正式快照替换当前故事线状态。
11. 旧生成段被新正文替换。
12. 页面退出重写模式，清空重写指令。

### 重写取消

- 用户在正文流式阶段点击「取消生成」，本次重写取消。
- 用户在记录角色摘要阶段点击「取消生成」，本次重写也取消。
- 取消后，旧正式正文保持不变。
- 取消后，临时重写草稿从页面移除。
- 取消后，页面仍停留在重写模式。
- 取消后，重写指令保留。
- 取消后，页面提示本次生成已取消。

### 重写失败

失败包括：

- 正文生成失败。
- 摘要生成失败。
- 保存失败。
- 服务端判定目标段不可重写。

失败规则：

- 旧正式正文保持不变。
- 临时重写草稿从页面移除。
- 页面仍停留在重写模式。
- 重写指令保留。
- 页面展示错误提示。
- 摘要失败、保存失败等技术细节不暴露给用户。

不可重写错误推荐展示文案：

```text
当前段落不可重写
```

通用生成失败文案继续使用：

```text
生成失败，请稍后重试
```

## 页面规则

### 重写入口

- 仅最新 generated segment 展示「重写」按钮。
- initial segment 不展示「重写」按钮。
- 非最新 generated segment 不展示「重写」按钮。
- 故事线没有 generated segment 时，不展示「重写」入口。
- 页面处于 connecting、streaming、summarizing 状态时，不允许进入重写。

### 临时正文展示

续写和重写的临时正文展示位置不同：

- 续写：临时正文展示在故事线末尾。
- 重写：临时正文展示在目标段下方，旧正式正文仍保留。

重写临时正文推荐分隔文案：

```text
重写中
```

摘要阶段文案沿用：

```text
正在记录角色摘要...
```

### 离开页面确认

以下情况离开页面需要二次确认：

- 正在续写生成。
- 正在重写生成。
- 正在记录摘要。
- 存在未提交的初始正文草稿。
- 存在未提交的续写草稿。
- 存在未提交的重写草稿。

如果用户确认离开，并且当前存在进行中的生成任务，则取消本轮生成。

## 服务端规则

### 协议

继续复用 WebSocket `story.continue` 客户端消息，`StoryContinuePayload` 新增 `rewrite` 模式。

推荐请求结构：

```ts
{
  mode: "rewrite";
  storylineId: StorylineId;
  segmentId: StorylineSegmentId;
  instruction: string;
}
```

说明：

- `instruction` 表示重写指令。
- `segmentId` 表示被重写的 generated segment。
- 生命周期沿用现有事件：

```text
story.started
-> story.chunk*
-> story.summary.started
-> story.completed | story.cancelled | story.error
```

`story.completed` 不需要新增字段。前端仍以 `story.completed.storyline` 作为唯一正式快照来源，并通过完整快照刷新页面。

### 服务端校验

服务端不能只依赖前端隐藏按钮，必须校验：

- storyline 必须存在。
- storyline 必须属于当前登录用户。
- segment 必须存在。
- segment 必须属于该 storyline。
- segment 必须是 generated segment。
- segment 必须是该 storyline 最新的 generated segment。

如果不满足可重写条件，返回新增错误码：

```text
STORY_SEGMENT_NOT_REWRITABLE
```

前端收到该错误码后展示「当前段落不可重写」。

### 并发控制

重写使用故事线级锁。

同一故事线同一时间只能执行一个 append 或 rewrite。若故事线正在生成，新的 append 或 rewrite 请求返回现有忙碌语义。

### Prompt 输入

重写 prompt 必须由服务端组装，前端不传旧正文或上下文。

重写 prompt 应包含：

- previousSummary。
- 初始故事正文。
- 目标生成段之前的近期历史。
- 目标生成段的原续写指令。
- 目标生成段的原生成正文。
- 用户本次输入的重写指令。

重写输出规则：

- 只输出替换目标段的新正文。
- 不重复输出初始故事正文。
- 不输出旧生成正文。
- 不输出标题、解释、列表、调试信息或“以下是重写”等前缀。
- 新正文需要承接目标段之前的上下文。
- 新正文需要参考旧生成正文中仍然合理的部分，但必须优先服从重写指令。

### 摘要处理

重写成功必须重新生成当前角色摘要。

摘要提取输入应使用：

- previousSummary：目标生成段保存的 previousSummary。
- 初始故事正文。
- 目标生成段之前的近期历史。
- 当前指令：本次重写指令。
- generatedText：本次重写生成的新正文。

不得直接使用重写前的当前摘要作为 previousSummary，否则旧版本正文中的角色状态可能污染新版本。

### 保存规则

重写成功后，服务端需要在同一事务中完成：

1. 更新目标 generated segment 的 text。
2. 更新目标 generated segment 的 instruction 为本次重写指令。
3. 更新目标 generated segment 的 model、elapsedMs、token usage 等生成元数据。
4. 更新故事线当前角色摘要。
5. 更新 storyline.updatedAt。

事务成功后，返回完整 `CompletedStorylineSnapshot`。

保存语义：

- 不新增 generated segment。
- 不改变 segment orderIndex。
- 不改变 segmentCount。
- 目标段 id 可以保持不变。
- latestGeneration.segmentId 仍指向被替换的目标段。
- 列表 preview 使用替换后的最新段正文。
- 重写成功视为故事线更新，列表中该故事线上浮。

如果摘要生成失败、保存失败或用户取消，则整个重写失败，旧正文和旧摘要都不能被修改。

## 数据模型要求

本期需要为 generated segment 保存 previousSummary。

推荐方案是在 `storyline_segment` 表上增加 nullable JSON 字段，例如：

```text
previous_summary_json
```

规则：

- initial segment 的 previous_summary_json 为空。
- generated segment 必须保存生成前角色摘要快照。
- 首轮 generated segment 保存空摘要。
- 后续 append generated segment 保存 append 前的当前摘要。
- rewrite 不修改 previous_summary_json，因为目标段的生成前状态不变。

由于本项目是本地实验性质的玩具项目，本期不考虑旧数据兼容。迁移可以按实现便利选择直接重建、清空或严格迁移。

## 前端规则

### 状态模型

前端需要区分当前生成意图：

- append：续写。
- rewrite：重写最新生成段。

建议在页面状态中额外保存：

- 当前输入模式。
- 续写草稿。
- 重写草稿。
- 正在重写的 segmentId。
- 重写临时正文。

`connecting`、`streaming`、`summarizing` 仍可作为通用生成阶段。页面根据当前生成意图区分临时正文展示位置和完成后的收尾行为。

### 输入区文案

续写模式沿用现有文案：

- 标签：续写指令。
- 按钮：生成续写。

重写模式使用：

- 标签：重写指令。
- 按钮：生成重写。
- 次要按钮：取消重写。

重写占位文案推荐：

```text
例如：不要转变场景，文风更加轻快，增加对气味的描写
```

### 完成处理

重写完成后：

- 使用 `story.completed.storyline` 替换当前正式故事线状态。
- 清空重写临时正文。
- 清空重写指令。
- 退出重写模式。
- 保留续写草稿。
- 展示完成后的正式故事正文。

### 失败和取消处理

重写失败或取消后：

- 当前正式 storyline 不变。
- 清空重写临时正文。
- 保留重写指令。
- 保持重写模式。
- 保留续写草稿。

## 验收标准

- 有 generated segment 的故事线，最新生成段显示「重写」按钮。
- 没有 generated segment 的故事线，不显示「重写」按钮。
- 非最新 generated segment 不显示「重写」按钮。
- 点击「重写」后，底部输入区切换为重写模式。
- 续写草稿和重写草稿互不覆盖。
- 重写指令为空时不能提交。
- 提交重写后，旧正式正文仍保留。
- 重写流式正文展示在目标段下方。
- 正文流式完成后，页面进入「正在记录角色摘要...」状态。
- 重写成功后，旧生成段被新正文原地替换。
- 重写成功后，segmentCount 不变。
- 重写成功后，列表 preview 使用新正文。
- 重写成功后，updatedAt 更新，故事线在列表中上浮。
- 重写成功后，重写指令清空，页面回到续写模式。
- 重写成功后，续写草稿保持不变。
- 重写取消后，旧正式正文不变。
- 重写取消后，临时重写正文消失。
- 重写取消后，重写指令保留。
- 重写失败后，旧正式正文和旧角色摘要都不变。
- 服务端拒绝非最新 generated segment 的重写请求。
- 服务端拒绝 initial segment 的重写请求。
- 服务端拒绝跨故事线或跨用户 segment 的重写请求。
- 重写 prompt 中包含原生成正文和用户重写指令。
- 重写摘要使用目标段保存的 previousSummary，而不是重写前的当前摘要。
- 摘要失败、取消或保存失败时，重写不落库。

## 后续演进

如果一期验证有效，后续可以扩展：

- 支持重写任意历史生成段。
- 引入重写版本记录和恢复能力。
- 引入分支故事线。
- 把 previousSummary 泛化为 previousState。
- 将角色摘要扩展为角色、事件、世界规则、伏笔等更完整的 CanonSnapshot。
- 为重写前后正文提供差异对比。
