# 从设定开始创建故事 PRD

## 背景

当前创建故事主要依赖用户直接输入故事正文和续写指令。这个流程适合用户已经有明确开场文本的场景，但对“先有世界观、人物关系、题材氛围，再慢慢展开故事”的创作方式支持不足。

本期新增「从设定开始」模式，让用户可以先沉淀一份可复用设定，再基于设定输入开场方向，由系统生成故事开端。设定以普通文本保存，不要求用户按固定字段填写。

## 目标

- 在创建故事流程中新增「从设定开始」入口。
- 用户可以查看自己保存过的设定，并选择其中一份继续创建故事。
- 用户可以输入灵感，让系统补全成一份更完整的设定。
- 用户可以保存补全后的设定，供本次和后续创建故事复用。
- 用户可以基于已保存设定输入开场方向，并进入现有故事创建生成流程。
- 新模式不影响当前默认的「正文 + 续写指令」创建方式。

## 非目标

- 本期不支持编辑已保存设定。
- 本期不支持删除已保存设定。
- 本期不做设定字段结构化。
- 本期不提供设定模板、分类、搜索、筛选或收藏。
- 本期不支持分享设定或查看他人设定。
- 本期不保留未保存的设定草稿或开场草稿。
- 本期不改变已有创建故事模式的默认入口和基础交互。

## 用户场景

### 从已有设定开始

用户已经保存过一份世界观或人物关系设定，希望快速用它创建新故事。

1. 用户进入创建新故事页面。
2. 用户点击「从设定开始」。
3. 用户在设定列表中选择一份已保存设定。
4. 用户查看设定详情，确认使用。
5. 用户输入本次故事的开场方向。
6. 用户点击「开场」，系统基于设定和开场方向生成故事。

### 先补全设定再开始

用户只有零散灵感，希望系统先整理成完整设定，再用这份设定创建故事。

1. 用户进入创建新故事页面。
2. 用户点击「从设定开始」。
3. 用户点击「新设定」。
4. 用户输入灵感。
5. 用户点击「补全设定」。
6. 系统生成一份详细设定。
7. 用户保存设定。
8. 保存成功后，用户进入基于该设定创建故事的页面。

## 核心概念

### 设定

设定是用户保存的创作基础材料，可以包含题材、世界观、人物、关系、冲突、氛围、规则等内容。

设定以普通文本形式展示和保存。系统不要求设定必须包含固定字段，也不限制设定的表达格式。

### 灵感

灵感是用户在创建设定时输入的原始想法。灵感可以很短，也可以是一段完整描述。

灵感只用于本次补全设定。用户离开创建设定页面后，未保存的灵感不保留。

### 开场

开场是用户基于某份设定，为本次新故事输入的起始方向。

开场可以描述第一幕、主角当前处境、想看的冲突、叙事语气或任意创作要求。用户离开从设定创建故事页面后，未提交的开场不保留。

## 产品入口

创建新故事页面默认仍展示现有的「正文 + 续写指令」模式。

在创建新故事页面顶部区域新增「从设定开始」入口。用户点击后，进入设定列表。

「从设定开始」是创建故事流程内的一个分支，不作为独立的应用主入口展示。

## 页面与交互

### 设定列表页

设定列表页用于展示当前用户保存过的设定。

页面内容：

- 返回按钮：返回现有创建故事页面。
- 新设定按钮：进入创建设定页面。
- 设定列表：展示当前用户已保存的全部设定。

列表规则：

- 最新创建的设定展示在最上方。
- 每个设定项应展示足够的信息，帮助用户判断内容，例如标题摘要或正文前若干行。
- 当没有已保存设定时，展示空状态，引导用户创建新设定。
- 点击设定项后，进入设定详情页。

本期限制：

- 不提供编辑入口。
- 不提供删除入口。
- 不提供批量管理能力。

### 创建设定页

创建设定页用于把用户灵感补全成完整设定。

页面内容：

- 返回按钮：返回设定列表页。
- 灵感输入框：多行文本输入框。
- 主按钮：「补全设定」。

输入规则：

- 灵感输入框支持多行输入。
- 用户未输入内容时，不允许发起补全。
- 用户离开页面时，未保存内容静默清空，不弹确认提示。

补全中状态：

- 用户点击「补全设定」后，主按钮进入 loading 状态。
- loading 期间主按钮不可重复点击。
- loading 期间灵感输入框不可编辑。
- 系统输出内容应在输入框下方流式展示。

补全成功：

- 系统生成结束后，展示保存按钮。
- 用户可以阅读补全后的设定内容。
- 用户点击保存后，系统保存这份设定。
- 保存成功后，进入基于该设定创建故事的页面。

补全失败：

- 展示 toast 提示。
- 清空已生成的补全内容。
- 灵感输入框恢复可编辑。
- 用户可以修改灵感后重新补全。

保存失败：

- 不离开当前页面。
- 展示 toast 提示。
- 清空已生成的补全内容。
- 灵感输入框恢复可编辑。
- 用户可以重新发起补全。

### 从设定创建故事页

从设定创建故事页用于基于一份已保存设定生成新故事开端。

页面内容：

- 返回按钮：返回故事列表页。
- 设定内容：只读展示当前选中的设定。
- 开场输入框：多行文本输入框。
- 主按钮：「开场」。

输入规则：

- 开场输入框支持多行输入。
- 用户未输入内容时，不允许发起开场生成。
- 用户离开页面时，未提交的开场内容静默清空，不弹确认提示。

生成行为：

- 用户点击「开场」后，系统基于设定内容和开场输入生成故事。
- 本次生成进入现有创建故事的横向阅读流程。
- 生成中的内容展示在横向第二页，保持与现有创建故事流程一致。
- 横向第一页保留展示设定内容和用户输入的开场。

生成成功：

- 新故事创建成功。
- 用户进入新故事的正式阅读状态。

生成失败：

- 删除临时生成页。
- 返回第一页。
- 展示 toast 提示。
- 开场输入框恢复可编辑。
- 用户可以修改开场内容并重新点击「开场」。

### 设定详情页

设定详情页用于查看已保存设定，并从该设定开始创建故事。

页面内容：

- 返回按钮：返回设定列表页。
- 设定内容：完整展示设定文本。
- 主按钮：「从设定开始」。

交互规则：

- 用户点击「从设定开始」后，进入从设定创建故事页。
- 设定内容只读展示。
- 本期不提供编辑或删除操作。

## 状态与异常

### 草稿处理

- 灵感草稿不跨页面保留。
- 开场草稿不跨页面保留。
- 用户离开相关页面时，草稿静默清空。
- 草稿清空不需要二次确认。

### 重复提交

- 补全设定过程中，不允许重复点击「补全设定」。
- 保存设定过程中，不允许重复点击保存按钮。
- 开场生成过程中，不允许重复点击「开场」。

### 错误提示

以下场景需要 toast 提示：

- 补全设定失败。
- 保存设定失败。
- 基于设定生成故事失败。

错误提示应说明当前操作失败，并引导用户重试。错误文案不需要暴露底层原因。

## 验收标准

- 创建新故事页面默认仍展示现有「正文 + 续写指令」模式。
- 创建新故事页面提供「从设定开始」入口。
- 用户点击「从设定开始」后，可以看到设定列表。
- 设定列表按创建时间倒序展示当前用户已保存设定。
- 设定列表为空时，展示空状态并引导创建新设定。
- 用户可以从设定列表进入创建设定页面。
- 用户可以输入灵感并点击「补全设定」。
- 补全设定期间，按钮 loading、不可重复点击，输入框不可编辑。
- 补全输出以流式方式展示。
- 补全失败时，toast 提示，清空补全输出，输入框恢复可编辑。
- 补全成功后，用户可以保存设定。
- 保存成功后，进入基于该设定创建故事的页面。
- 保存失败时，toast 提示，不跳转，清空补全输出，输入框恢复可编辑。
- 用户可以从设定列表点击设定项进入设定详情页。
- 设定详情页完整展示设定内容，并提供「从设定开始」按钮。
- 从设定创建故事页展示设定内容和开场输入框。
- 用户点击「开场」后，系统基于设定和开场输入生成故事。
- 生成内容展示在横向第二页，第一页保留设定内容和用户输入的开场。
- 生成失败时，临时第二页被移除，用户回到第一页并可修改开场后重试。
- 本期所有已保存设定均不可编辑、不可删除。
- 用户离开创建设定页或从设定创建故事页时，未保存草稿静默清空。

## 风险与取舍

### 设定不可编辑会增加返工成本

本期不提供编辑能力，用户如果对设定不满意，只能重新创建一份。这样可以降低首期复杂度，但会让长设定的修正成本较高。

### 纯文本设定的复用质量依赖生成结果

设定不做结构化，用户保存和复用都更自由，但系统无法稳定识别人物、世界观、冲突等字段。首期目标是验证「从设定开始」的创作链路，而不是建立完整设定管理系统。

### 草稿不保留可能造成输入丢失

灵感和开场草稿离开页面即清空，符合草案中的轻量策略，但用户误触返回时可能丢失输入。首期通过明确页面层级和返回行为降低误触成本。
